## Python Quickstart <a name="quick_start"></a>

Prerequisites: You need Python 3.10 or newer and `pip` for installing packages.

- **Create a Python virtual environment and activate it**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

- **Install ADK**

```bash
pip install google-adk
```

- **Create a new project using `adk create` command**

```bash
adk create my_agent
```

This command creates the following files in my_agent folder:

```bash
my_agent/
    agent.py      # main agent code
    .env          # API keys or project IDs
    __init__.py
```

- **Update the agent definition:**

The `agent.py` file contains an agent definition. You can define tools for the agent to use.
Update `agent.py` code to include a `get_current_time` tool for use by the agent, as follows:

```python
from google.adk.agents.llm_agent import Agent

# Mock tool implementation
def get_current_time(city: str) -> dict:
    """Returns the current time in a specified city."""
    return {"status": "success", "city": city, "time": "10:30 AM"}

root_agent = Agent(
    model='gemini-flash-latest',
    name='root_agent',
    description="Tells the current time in a specified city.",
    instruction="""You are a helpful assistant that tells the current time in cities.
    Use the 'get_current_time' tool for this purpose.""",
    tools=[get_current_time],
)
```

- **Set your API key**

This agent network uses a Gemini model which requires an API key. Get an API key from
[Google AI Studio](https://aistudio.google.com/app/apikey) and write it into your `.env`
file via:

```bash
echo 'GOOGLE_API_KEY="YOUR_API_KEY"' > .env
```

- **Run your agent via command-line interface**

```bash
adk run my_agent
```
Image below shows a sample interaction with the agent.

![Agent interaction]({{ site.baseurl }}/images/my_agent_cli.png)

- **Run your agent via web interface**

The command below starts a web server with a chat interface for your agent. You can
access the web interface at http://localhost:8000. Select the agent at the upper
left corner and type a request.

```bash
adk web --port 8000
```

![Agent interaction]({{ site.baseurl }}/images/my_agent_web.png)

- **Run your agent by sending requests to an API server**

The command below will launch a local web server on http://localhost:8000

```bash
adk api_server --auto_create_session
```

The `--auto_create_session` flag automatically generates a new session if one
does not already exist when running the application. You can use `curl` commands
to interact with the local web server.

To check server's health or it's version:

```bash
curl -X GET http://localhost:8000/health
curl -X GET http://localhost:8000/version
```

To list the available agent network:

```bash
curl -X GET http://localhost:8000/list-apps
```

To send a request to `my_agent` agent network:

```bash
curl -X POST http://localhost:8000/run \
  -H "Content-Type: application/json" \
  -d '{
    "appName": "my_agent",
    "userId": "u_123",
    "sessionId": "s_abc",
    "newMessage": {
      "role": "user",
      "parts": [{"text": "Hello, can you help me?"}]
    }
  }'
```

## Building a Multi-tool Agent <a name="multi_tool"></a>

Simply, define another function in `agent.py`, e.g.:

```python
# Mock tool implementation
def get_current_weather(city: str) -> dict:
    """Returns the current weather in a specified city."""
    return {"status": "success", "city": city, "weather": "Sunny with a temperature of 77 degrees Fahrenheit"}
```

Add the new function name to `tools` list in `root_agent`, and update the description/instruction:

```python
root_agent = Agent(
    model='gemini-flash-latest',
    name='root_agent',
    description="Tells the current time or weather in a specified city.",
    instruction="""You are a helpful assistant that tells the current time or weather in cities.
    Use the 'get_current_time' or 'get_current_weather' tools for these purposes.""",
    tools=[get_current_time, get_current_weather],
)
```

## Related Work <a name="related"></a>

Previous approaches for reducing LLM pretraining costs fall into two main categories: (1) parameter-preserving methods, which improve training efficiency without modifying model size, and (2) parameter-reducing methods, which factorize weight matrices directly. In this blog, we focus on parameter-reducing methods because they offer greater potential for lowering LLM pretraining costs.

Existing approaches to maintaining orthonormality fall into three categories: (1) initializing weight
matrices as orthonormal, and not compensating for the inevitable deviation from orthonormality
during unconstrained optimization; (2) employing soft regularizers, which introduce additional hyperparameters for encouraging orthonormality;
and (3) periodically projecting weights back onto the orthonormal manifold. The latter approach is most closely related to the TSVD method and is discussed in this subsection.

The [LORO](https://openreview.net/forum?id=i0zzO7Hslk) method utilizes Riemannian optimization to maintain weight constraints. As the mathematical context, a manifold is a topological space that is locally flat but could be curved globally, such as a plane, sphere, torus, or saddle-shaped surface. A Riemannian manifold provides a way to measure distances, angles, etc. using a Riemannian metric. In Riemannian optimization variables are constrained to lie on a smooth manifold $\mathcal{M}$ (such as a sphere), rather than a flat Euclidean space $\mathbb{R}^n$. The core concepts for Riemannian optimization are thus:

- **The Manifold ($$\mathcal{M}$$)**: The search space.
- **Tangent Space ($T_x\mathcal{M}$)**: At any point $x \in \mathcal{M}$, the tangent space is a linear approximation of the manifold's local geometry. Gradients are computed in this space.
- **Riemannian Gradient**: The projection of the standard Euclidean gradient onto the tangent space, denoted as $\operatorname{grad} f(x) = \text{P}_{T_x\mathcal{M}}(\nabla f(x))$.
- **Retraction**: A mapping $R_x: T_x\mathcal{M} \to \mathcal{M}$ that moves an element from the tangent space back onto the manifold.

LORO searches on the *low-rank matrix manifold*, defined as the set of matrices with a fixed rank $r$. Each matrix $W$ has a *unique representation*, eliminating redundancy during the search process. However, the retraction operation requires an SVD operation, which is computationally expensive. The cost, in the number of FLOPs, for a matrix $W \in \mathbb{R}^{m \times n}$ is $mn^2 + n^3$.

To manage this cost, LORO executes the SVD retraction sparingly, every $K = 500$ steps. In contrast, the QR decomposition in TSVD optimizes over the *Stiefel manifold*, i.e. the set of all matrices with orthonormal columns, denoted as $St(n,r) = \{ X \in \mathbb{R}^{n \times r} \mid X^\top X = I_r \}.$
This approach may result in *non-unique representations*, since different factors ($U, \Sigma, V$) can represent the same product $W$, which could be a limitation. However, the QR decomposition is significantly more efficient than the SVD operation.
Thus, the assumption of TSVD is that the computational efficiency of the projection onto the Stiefel manifold outweighs the theoretical benefits of unique representation on the fixed-rank manifold. Indeed, the results in this paper suggest that, given the massive scale of current and future LLMs, the significant reduction in retraction overhead justifies the inherent redundancy in factorized representation, making TSVD a more practical approach for large-scale optimization than other current methods.

Distinct from the weight-centric strategies mentioned above, [COLA](https://arxiv.org/pdf/2502.10940) leverages the low-rank nature of LLM activations by replacing Multilayer Perceptron (MLP) and attention projection layers with low-rank autoencoders. Its memory-efficient variant, COLA-M, further reduces overhead by utilizing low-rank activations, while both frameworks preserve the original query, key, and value projection structures.

In summary, low-rank weight matrix representations offer the most significant reductions in pretraining memory and computational overhead. The integration of orthonormality constraints helps mitigate the performance trade-offs typical of low-rank methods. However, due to high computational costs, previous techniques have not maintained orthonormality throughout the entire training duration. The TSVD method proposed in this paper ensures strict orthonormality at every iteration and, to the best of our knowledge, is the first approach to achieve this goal in a pretraining setting.

## The TSVD Framework <a name="framework"></a>

In this section, SVD and TSVD are reviewed, and the TSVD layer, model, and its corresponding training methodology are introduced. Next, QR decomposition, caching, and rank selection methods are described. The TSVD algorithm is summarized in **Algorithm 1**

![Algorithm 1]({{ site.baseurl }}/images/Algorithm_1.png)

### Singular Value Decomposition (SVD) <a name="svd"></a>

SVD is a fundamental matrix factorization method widely used in linear algebra, statistics, and machine learning. At its core, it expresses any matrix as a product of three simpler matrices. For any $m \times n$ matrix $W$, the SVD is 

$$W = U \Sigma V^T \tag{1}$$

where $U \in \mathbb{R}^{m \times m}$ comprises the left singular vectors (orthonormal matrix), $\Sigma \in \mathbb{R}^{m \times n}$ are singular values (diagonal matrix with non-negative entries), and $V \in \mathbb{R}^{n \times n}$ comprises the right singular vectors (orthonormal matrix). Thus, SVD decomposes a linear transformation into three distinct geometric operations: $V^T$ rotates the input into a new coordinate system, $\Sigma$ scales the vector along orthogonal axes, and $U$ rotates the result into the output's coordinate system.

For any $m \times n$ matrix $W$, Truncated SVD (TSVD) is a low-rank approximation of SVD, defined as

$$W \approx  U_k \Sigma_k V_k^T \tag{2}$$

where $U_k$  is the first $k$ columns of $U$, $\Sigma_k$ is the diagonal matrix with the top $k$ singular values, and $V_k$ is the first $k$ columns of $V$. Thus, the truncated version discards the smaller singular values and their corresponding directions.

### The TSVD Terminology <a name="terminology"></a>

The TSVD framework consists of three core abstractions. A **TSVD layer** approximates a full weight matrix $W \in \mathbb{R}^{m \times n}$ via truncated factorization $W \approx U_k \Sigma_k V_k^T$. Here, $U_k \in \mathbb{R}^{m \times k}$, $\Sigma_k \in \mathbb{R}^{k \times k}$, and $V_k^T \in \mathbb{R}^{k \times n}$ are initialized as unconstrained trainable parameters. During the forward pass, the layer enforces structural constraints: $U_k$ and $V_k$ are projected onto orthonormal matrices via QR decomposition, while $\Sigma_k$ is constrained to a positive-valued diagonal vector. Constraining $U_k$ and $V_k$ to be orthonormal is what provides the stability benefits established in prior work on orthogonal and semi-orthogonal parameterizations. Second, a **TSVD model** is a neural network that replaces standard dense weight matrices with TSVD layers. Third, **TSVD training** is the end-to-end training process of a TSVD model, wherein structural orthonormality constraints are maintained across every training iteration.

### QR Decomposition <a name="qr"></a>

Low-rank approximation of $W$ reduces the number of parameters from $mn$ to $mk + k + kn = k(m+n+1) \approx k(m+n)$. For example, if $W$ is a $1000$ by $800$ matrix, and $k = 128$, the number of parameters reduces from $800,000$ to $128*(1000 + 800 +1) = 230,528$, i.e. by $\approx 71\%$. The benefits are twofold: (1) lower memory requirements for storing parameters, gradients, and optimizer states, and (2) reduced computational cost, as measured in FLOPs, because multiplying the input by a low-rank approximation of $W$ is less costly than multiplying the input by $W$. The TSVD framework relies on QR decomposition in the forward pass to enforce orthonormality on unconstrained trainable parameters. The cost, in the number of FLOPs, for a matrix is $\in \mathbb{R}^{m \times k}$ is 

$$2mk^2 - \frac{2}{3}k^3 \tag{3}$$

### Caching <a name="caching"></a>

To mitigate the computational overhead of QR decomposition, the structure of gradient accumulation can be leveraged. While larger batch sizes make training of LLMs more stable, hardware constraints often require splitting an effective batch into smaller mini-batches. For example, an effective batch of 1024 is processed as four mini-batches of 256, with gradients accumulated before a single parameter update. The TSVD training includes a caching mechanism that computes the QR decomposition during the initial mini-batch and reuses the result for all subsequent mini-batches within the same update. This approach ensures that the expensive orthonormalization occurs only once per parameter update, effectively amortizing the computational cost while preserving the benefits of orthonormality.

### Rank Selection <a name="rank"></a>

Existing low-rank methods typically apply a uniform rank across all layers and weight matrices, regardless of their functional roles. However, this choice may be suboptimal, because weight matrices in different components of a transformer decoder layer can require different ranks to perform well.

The TSVD framework employs the spectral energy of weight matrices of pretrained models as a heuristic for rank selection. First, SVD is applied to the weight matrices of the pretrained model, obtaining the diagonal matrix $\Sigma$ with singular values $\sigma_1, \sigma_2, \dots, \sigma_n$. The total energy of a full-rank matrix $W$ is then defined as the sum of these values. Second, to determine the rank for the low-rank approximation, the energy for a truncated set of ranks is calculated.  The *compression rank*, $r_{\alpha}(W)$, to preserve at least $\alpha$ (e.g., $95\%$) of the total energy is then defined as

$$r_\alpha(W) = \min \left\{ k \mid \frac{\sum_{i=1}^{k} \sigma_i^2}{\sum_{j=1}^{n} \sigma_j^2} \ge \alpha \right\} \tag{4}$$

The value of $\alpha$ is selected based on the desired reduction in model's parameter count and is used to determine the compression rank of the weight matrices across different layers. Since compression rank generally varies across layers -- for example, MLP weight matrices typically exhibit higher compression ranks than attention weight matrices -- this approach supports variable rather than uniform rank selection. In the next section, we analyze the compression ranks across models of various sizes within an LLM family to determine their configurations.

## Configuring Compression Ranks <a name="compression"></a>

Compression ranks are analyzed across the experimental suite of full-parameter Llama-style LLMs, ranging from 60M to 1.3B parameters. Compression rank (Eq. 4) is computed for each linear weight matrix within the transformer decoder layers. Those are the query, key, value and out projection within the attention mechanism and the gate, up and down projections in the MLP. The compression ranks for the models in the experimental suite are provided in **Figure 4**. Across layers, the compression ranks of different projection types (query, key, etc.) are consistent, with the exception of the earliest layers. Motivated by this stability, compression ranks are averaged across layers for comparison across model scales.

![Figure 4]({{ site.baseurl }}/images/Figure_4.png)

**Figure 1a** illustrates the compression ranks across the different model sizes in the experimental suite. The main observation is that they scale approximately linearly with model size. Notably, the major architectural parameters (**Table 1**), that is, the number of transformer layers $n_{\text{layers}}$, the number of heads per layer $n_{\text{heads}}$, the hidden dimension $d_1$, and the MLP intermediate dimension $d_2$, scale uniformly across the models. When normalizing compression ranks (we chose the  compression rank of the out projection) of the model (**Figure 1b**), the relative proportions between ranks of different projections are nearly constant across model sizes. Overall, these results indicate that *compression ranks measured on smaller models can be used to estimate those of larger models algorithmically*.

![Figure 1]({{ site.baseurl }}/images/Figure_1.png)

To assess the generality of the findings and highlight potential deviations, the analysis was extended to large, publicly available model families: Llama-2, Llama-3.1, and Olmo 3. Detailed results are provided in paper's Appendix. The results show that the compression ranks determined for small models can be used to predict the compression ranks at larger model sizes given the correct scaling of its hyperparameters.

![Table 1]({{ site.baseurl }}/images/Table_1.png)

For the pretraining experiments in [Pretraining Performance](#pretraining), the consistent relationships observed between the compression ranks of different functional components in **Figure 1a** guided the rank selection; E.g., the compression ranks for the value and output projections layers were $18\%$ larger than those for the query and key projections. The compression rank ratios were then maintained when scaling to larger target architectures in the rest of the experiments. That is, while absolute ranks are scaled according to a target parameter budget, the relative rank selections adhere to these relationships.

## Experiments <a name="experiments"></a> 

This section details preliminary experiments establishing hyperparameters, followed by a performance comparison across model scales for TSVD, full-parameter, and low-rank architectures during pretraining and evaluation. Finally, ablation studies examine the impact of the QR decomposition, caching mechanism, and the role of variable rank selection.
    
### Hyperparameter Setup <a name="hyper"></a>

To tune hyperparameters across the TSVD experimental suite, the Maximal Update Parametrization framework was employed, which mitigates the prohibitive computational cost of optimization in large neural networks. By properly scaling initialization and learning rates, $\mu$P guarantees stable forward-pass activations and backward-pass gradient updates as model width increases. Crucially, this property enables zero-shot hyperparameter transfer, allowing optimal learning rates identified on small, computationally cheap models to transfer directly to significantly larger models without additional tuning. Accordingly, TSVD hyperparameter searches used the lightweight Llama-60M variant, requiring approximately 30 minutes of compute.

### Pretraining Evaluation <a name="evaluation"></a>

This section provides a performance comparison across model scales for TSVD, full-parameter, and low-rank architectures during pretraining and evaluation.

#### Pretraining Performance <a name="pretraining"></a>

A series of Llama-style LLMs with scales ranging from 60M to 7B parameters were pretrained in the language modeling task. The experimental framework strictly followed the benchmark protocols established in the literature. However, the benchmarks were ported to the HuggingFace ecosystem, using *accelerate* for launching distributed runs across GPUs. Four architectural configurations were evaluated: dense full-parameter models, models with low-rank approximations of linear and attention layers, models with CoLA-based linear layers, and the proposed TSVD approach. This enables comparison of TSVD with traditional and state-of-the-art reparameterization methods.

Models were trained on the Colossal Clean Crawled Corpus, a massive web-scale dataset derived from Common Crawl. C4 uses strict heuristic filtering to remove low-quality, repetitive, and offensive data. Comprising of 365M documents and 150B tokens, C4 serves as a standard benchmark for pretraining prominent models like T5.

![Table 2]({{ site.baseurl }}/images/Table_2.png)

The results for models up to 1.3B are included in **Table 2**. Across all model scales, TSVD models consistently achieved lower perplexity than their full-parameter counterparts. TSVD models contained between $24\%$ and $51\%$ fewer parameters, yielding a corresponding reduction in the memory footprint for parameters, gradients, and optimizer states. Note that while the full-parameter, low-rank, and CoLA experiments were designed to replicate results reported in the literature, the modern Hugging Face implementation yielded significantly improved accuracies for them. These enhancements may be attributed to several factors, including modernized weight initialization schemes, refined tokenization processes, and the utilization of better optimization hyperparameters.

![Table 3]({{ site.baseurl }}/images/Table_3.png)

The scale-up properties of TSVD were demonstrated further on a Llama-7B model, which takes an average of 10 full days to pretrain on an NVIDIA H200 GPU node. The results are presented in **Table 3**. Although the TSVD model’s perplexity is $\approx 3\%$ higher than that of the full-parameter model, it contains over 2B fewer parameters -- significantly reducing memory overhead for parameters, gradients, and optimizer states. Furthermore, as shown in **Table 3**, the perplexity gap between the full-parameter and TSVD models narrows as training progresses, decreasing from 0.48 at 50k steps to 0.30 at 100k, and 0.19 at 150k. Given the observed trajectory, further training would likely narrow this performance gap even more. These results demonstrate that TSVD scales effectively to larger models, offering a robust and memory-efficient approach to large-scale pretraining.

![Table 4]({{ site.baseurl }}/images/Table_4.png)

#### Benchmark Performance <a name="benchmark"></a>

Having established that TSVD models perform well in pretraining task, It is important to assess pretrained model transfer to application benchmarks. To this end, the pretrained full-parameter and TSVD models were evaluated in key commonsense reasoning and text/context understanding tasks: HellaSwag, PIQA, and LAMBADA. Detailed accuracy results are reported in **Table 4**. The experimental results demonstrate that the TSVD models consistently match or outperform full-parameter models across the entire suite of evaluation benchmarks, with the sole exception of the Llama-350M variant on the LAMBADA dataset. Consequently, aligning closely with its strong pretraining trajectory, TSVD maintains competitive generalization and robust performance when transferred to external evaluation tasks.

### Ablation Studies <a name="ablation"></a>

This section examines the impact of the QR decomposition, caching mechanism, and rank selection.

#### Impact of QR Decomposition <a name="qr_ablation"></a>

The TSVD framework uses QR decomposition to maintain orthonormality, avoiding the computationally expensive SVD operation in Riemannian optimization. The respective computational costs are given by Equations 3 and 5. **Figure 3** plots the computational cost of SVD vs. QR decomposition for various ranks, showing that QR decomposition requires far fewer FLOPs.

![Figure 2]({{ site.baseurl }}/images/Figure_2.png)

#### Impact of Caching Mechanism <a name="cache_ablation"></a>

Gradient accumulation is a training technique that partitions an effective batch into smaller mini-batches, processing them sequentially while accumulating their gradients to execute a single parameter update once the full batch size is reached. The TSVD framework computes the QR decomposition during the initial mini-batch, caches the results, and reuses them across subsequent mini-batches, effectively amortizing orthonormalization costs. Consequently, an increased number of gradient accumulation steps leads to greater amortization of the QR decomposition overhead.

Full-parameter and TSVD Llama models (60M and 130M) were pretrained across $G \in \{1, 2, 4, 8, 16, 32\}$ gradient accumulation steps. **Figure 2** shows that larger gradient accumulation steps and model sizes amplify TSVD’s training efficiency gains over full-parameter models. Note that at $G = 1$ (a single step), TSVD performs QR decomposition at every update without cache reuse, making it slower than the full-parameter model. However, as the number of gradient accumulation steps increases, the computational cost of QR decomposition is amortized across steps. The TSVD version thus outperforms the full-parameter version in wall-clock time, making it a more practical choice as the number of gradient accumulation steps increases.

![Table 5]({{ site.baseurl }}/images/Table_5.png)

#### Impact of Compression Rank Selection <a name="rank_ablation"></a>

While a uniform rank selection enforces a fixed rank across all layers and weight matrices irrespective of their functional roles, the TSVD framework computes the compression rank of each individual weight matrix based on its spectral energy, naturally accommodating variable rank selection across the architecture. To evaluate the impact of compression rank selections, four model scales were pretrained: Llama-60M, 130M, 350M, and 1.3B. At each scale, a TSVD model utilizing compression ranks (via spectral energy analysis) was compared against a uniform-rank baseline with fixed rank selections of 136, 240, 240, and 552, respectively. These uniform ranks were selected to match the total parameter count of the corresponding compression-rank models at each scale.

The experimental results are presented in **Table 5**. The compression-rank TSVD models consistently outperform their uniform-rank counterparts, with the exception of the 60M scale. Furthermore, the performance advantages of compression rank selection widen as model scale increases. The results show that compression rank selection outperforms uniform rank selection.

## Discussion and Future Work <a name="future"></a>

The TSVD experiments in this paper focused on dense models for two reasons: (1) to provide a fair comparison to prior low-rank pretraining methods, which were evaluated exclusively on dense architectures; and (2) to make sure that the approach scales to larger models. Having achieved these goals, a compelling next step is to extend it to Mixture-of-Experts (MoE) architectures, as the vast majority of state-of-the-art models rely on MoE architectures. Several other promising directions remain for future work. First, fine-tuning pretrained TSVD models on smaller, task-specific datasets is a natural next step. Second, investigating regularization strategies for $\Sigma$, to control the spectral norm of weight matrices and improve generalization. Third, exploring whether orthonormal matrices learned in smaller models can initialize corresponding matrices in larger models, while increasing the training efficiency.

## Conclusion <a name="conclusion"></a>

This paper introduces TSVD, a novel framework designed to reduce the parameter count and computational overhead of LLM pretraining. To our knowledge, TSVD is the first approach to maintain strict weight orthonormality throughout training without incurring prohibitive overhead, enabled by QR decomposition, an optimized caching mechanism, and a rank selection heuristic. Empirical evaluations show that TSVD models match or outperform their full-parameter counterparts across pretraining metrics and evaluation benchmarks. TSVD reduces the FLOPs required for LLM pretraining, lowering wall-clock time and GPU cost. It also reduces memory requirements, enabling larger models on existing hardware or the use of lower-tier GPUs, further reducing pretraining costs. The TSVD framework provides a foundation for more efficient pretraining of LLMs.
